## 🔴 الأهم: حل مشكلة التكرار الجذرية

لقيت إن نظام حماية "نسخة واحدة بس تشتغل" في كودك كان مكسور:

```js
// النظام القديم (مكسور):
process.kill(oldPid, "SIGTERM");  // ❌ ده مش بيشتغل على Replit أصلاً!
```

`process.kill` بيحاول يقفل عملية بـ PID، لكن على Replit كل إعادة تشغيل (deploy) بتحصل في حاوية (container) جديدة منعزلة عن القديمة — يعني الـ PID القديم مش حتى موجود في نفس البيئة، فالأمر بيفشل بصمت والنسختين (القديمة والجديدة) بتفضلوا شغالين مع بعض فترة، وكل واحدة بترد على الرسايل → **تكرار**.

**الحل:** نظام heartbeat جديد بـ `helpers/single-instance.js`:
- كل نسخة بتكتب "نبضة قلب" (timestamp) كل 20 ثانية في ملف
- لو نسخة جديدة بدأت ولقت نبضة حديثة (أقل من 60 ثانية) → بتخرج فورًا من غير ما تستقبل ولا رسالة
- لو لقت نبضة قديمة ميتة (أكتر من 60 ثانية، يعني النسخة القديمة فعلاً ماتت) → بتاخد الـ lock وتشتغل عادي

ده اختبرته بمحاكاة كاملة (نسخة شغالة + نسخة جديدة بتحاول تدخل + نسخة قديمة ميتة) وكل السيناريوهات شغالة صح.

⚠️ **لو لسه عندك مشكلة تكرار بعد رفع التحديث ده**: شوف الـ console logs، المفروض تشوف رسالة `🔒 [Lock] احنا النسخة الشرعية`. لو شفت `❌ [Lock] نسخة تانية شغالة`، يبقى فيه نسخة تانية شغالة فعلاً في مكان آخر (جهازك الشخصي مثلاً) — قفلها.

## 1️⃣ دمج الأوامر المشابهة (8 مجموعات)

كل المجموعات دي بقت أمر واحد بـ subcommands (مثلاً `/اقتصاد بروفايل`، `/اقتصاد محفظة`، إلخ):

| الأمر الجديد | الـ subcommands اللي جواه |
|---|---|
| `/اقتصاد` | بروفايل، محفظة، متجر، شراء، إعطاء، يومي |
| `/مانهوا` | إنشاء، إضافة-مصطلح، عرض-مصطلحات |
| `/رتبة` | انشاء، تعديل |
| `/عقوبة` | تحذير، اسكات، طرد، تبنيد، عرض |
| `/موسيقى` | تشغيل، إيقاف، تخطي، قائمة-تشغيل، توقف-مؤقت، استئناف |
| `/نسخ-احتياطي` | انشاء، استرجاع، تحديد-قناة |
| `/بوت` | حالة، اختبار، قناة-لوجز |
| `/بلوك` | رفع، قائمة |

**الأوامر القديمة (`/تحذير`، `/بروفايل`، `/تشغيل`، إلخ) محذوفة بالكامل** — مش هتظهر تاني، والكل لازم يستخدم الأسماء الجديدة المدموجة.

**`/مسح` و `/مسح-الكل` فضلوا منفصلين زي ما طلبت بالضبط** — مش جزء من أي دمج.

### ⚠️ ملاحظة تقنية مهمة عن الصلاحيات
بعض الأوامر القديمة كانت كل واحدة عندها صلاحية مختلفة (مثلاً `/طرد` يحتاج Kick Members، `/تبنيد` يحتاج Ban Members). Discord مش بيسمح بصلاحيات مختلفة لكل subcommand تحت أمر واحد، فعملت الحل ده: الأمر `/عقوبة` هيظهر لكل الأعضاء في قائمة الأوامر، لكن البوت بنفسه بيرفض التنفيذ برسالة واضحة لو الشخص مش عنده الصلاحية المطلوبة لكل subcommand بالتحديد. هيظهر الأمر للكل بصريًا، لكن مش هيقدر ينفّذه غير اللي عنده الصلاحية الصحيحة.

## 2️⃣ تعديل طريقة الكلام (الثلاث أوضاع)

| الوضع | الاسم الجديد | السلوك |
|---|---|---|
| `normal` | 🎩 0% شتايم | مش بيشتم خالص حتى لو شتموه |
| `free` | 😈 باد بوي 50% | بيشتم بس لو الشخص اللي بيكلمه شتمه هو |
| `toxic` | ☠️ إكستريم 100% | كل كلامه شتايم بشكل طبيعي ومنفتح جداً |

**ملحوظة:** الأمر `/تغيير-طريقة-الكلام` نفسه (الموجود في `commands/games-hub.js`) ما اتلمسش غير في الـ labels — هو نفس الأمر، بس النص اتحدّث.

## 3️⃣ أمر `/رول-ريأكشن` الجديد

```
/رول-ريأكشن رول:@العضو-المميز إيموجي:⭐ رسالة:اعمل ريأكشن لو حابب تنضم!
```

- البوت يبعت الرسالة ويحط الإيموجي عليها تلقائياً
- أي حد يعمل ريأكشن بنفس الإيموجي → ياخد الرول فوراً
- لو شال الريأكشن → الرول بيتشال منه تلقائياً
- البيانات بتتحفظ في `data/reaction-roles.json` — تفضل موجودة حتى لو البوت اتعمله restart

**محتاج صلاحية Manage Roles لاستخدام الأمر.**

## 🪜 خطوات الرفع على Replit

```bash
cp index.js index.js.backup4
cp database.js database.js.backup4
unzip -o zangi-bot-merged.zip
cp zangi-bot-merged/index.js .
cp zangi-bot-merged/database.js .
cp zangi-bot-merged/commands/games.js commands/
cp zangi-bot-merged/commands/games-hub.js commands/
cp zangi-bot-merged/helpers/single-instance.js helpers/
mkdir -p data
cp -n zangi-bot-merged/data/reaction-roles.json data/ 2>/dev/null || true
node --check index.js && node --check database.js && node --check commands/games.js && node --check commands/games-hub.js && node --check helpers/single-instance.js && echo "✅ تم كل حاجة بنجاح"
```

**⚠️ مهم جداً بعد الرفع:** أول ما تشغّل البوت، شوف الـ console — لازم Discord يحدّث قائمة الأوامر (ممكن ياخد لحظات أو لازم تعمل refresh للسيرفر/Discord client عشان تشوف الأوامر الجديدة وتختفي القديمة).
